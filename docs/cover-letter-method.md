# Cover Letter Method

This is the human-facing rationale behind the runtime rules in `references/cover-letter/`.

A useful cover letter is not a prose copy of the resume. It should explain why the candidate's real evidence matters for this role and why this role/employer is meaningful enough to discuss specifically.

The working method is:

1. **Find the evidence first.** Compare the JD with the candidate profile/resume and identify a small set of genuine match points before writing prose.
2. **Ask the candidate.** Check for real company/industry contact, a relevant story, and the angle the user wants emphasized. If there is no story, use known facts rather than inventing one.
3. **Build a bridge.** Explain what the candidate learned/can transfer from those experiences instead of repeating task bullets.
4. **Draft around one coherent reason.** A letter is usually stronger when paragraphs support a common idea rather than presenting unrelated mini-resume sections.
5. **Edit for relevance.** Remove weak/redundant paragraphs before compressing every sentence into generic language.
6. **Fact-check at the end.** Every candidate claim still needs grounding in the profile/current-session facts; company facts need evidence from the actual employer/job information.

The reusable Skill intentionally does not force one candidate's preferred paragraph count, punctuation style, sign-off or tone. Persistent style preferences belong in the user workspace.

If an employer explicitly asks applicants not to use AI-generated writing, Easy Apply should not ghostwrite the letter. It may help the user organize their own ideas or proofread text the user wrote.
